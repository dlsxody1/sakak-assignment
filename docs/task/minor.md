# 자잘한 것

큰 것(알고리즘·2단계 인증·배포)이 끝난 뒤에 본다. 지금 안 해도 동작에 문제 없다.

## 코드

### 단백뇨 등급 하드코딩

[parse-reference.ts:6](../../dashboard/src/entities/health-reference/lib/parse-reference.ts)에
`ponytail:` 주석으로 남겨둔 것.

```
PROTEINURIA_GRADES = ['음성', '약양성±', '양성(+1)', '양성(+2)', '양성(+3)']
```

기준이 `양성(+1)이상`인데 실제 값은 `양성(+1)`이라 완전일치가 안 된다.
등급 서열은 API가 주지 않아서 도메인 지식으로 넣었다.
**API에 없는 등급이 새로 오면 여기 추가한다.** 서열이 필요한 항목이 이거 하나라
범용 서열 테이블은 만들지 않았다.

### 번들 크기

ApexCharts가 라우트 청크에 약 970 kB를 더한다 (gzip 279 kB).
빌드가 500 kB 경고를 낸다. 동작에는 문제 없다.
줄이려면 차트를 동적 import로 쪼갠다 — 첫 화면에 차트가 보이므로 이득은 크지 않다.

### 컴포넌트 테스트 없음

`@testing-library/react`가 설치돼 있지 않고 vitest `setupFiles`도 없다.
지금 110개 테스트는 전부 순수 함수와 경계 검사다.

로직을 `lib/`로 다 빼놨기 때문에 **핵심은 이미 렌더링 없이 검증된다.**
컴포넌트 테스트가 필요해지는 시점(폼 검증 등 상호작용이 늘 때)에 세팅한다.

## 안 할 것

기록해두는 이유는 "빠뜨린 게 아니라 결정한 것"이기 때문이다.

- **골밀도 항목 숨기기** — 6회차 전부 결측이라 항상 `미측정`이다. 그래도 숨기지 않는다.
  검진 항목에 있는데 안 보이면 사용자는 그런 검사가 없는 줄 안다.
- **판정불가 세분화** — `기준 없음`과 `구간 밖`을 타입으로 쪼개지 않았다.
  화면에서는 이미 구분해서 보여주고 있고, 도메인 타입을 늘리면 소비하는 쪽이 다 늘어난다.
- **fixture 통합 스냅샷 테스트** — 126칸(6회차 × 21항목)을 통째로 고정하지 않는다.
  값 하나 바뀌면 126칸이 흔들리는데 어느 것도 왜 그런지 설명하지 않는다.
  회귀 기준 4개를 명시적으로 고정하는 편이 낫다.
