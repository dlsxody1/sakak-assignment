# 대시보드 (`/`)

앱의 유일한 화면. 앱 레벨 규칙은 [ux-design.md](../ux-design.md)에 있고 여기서 반복하지 않는다.

---

## 목적

**JTBD**: 검진 결과 6회차를 받았을 때, **지금 신경 써야 할 항목이 뭔지** 5초 안에 알고,
왜 그런지는 원할 때 파고들고 싶다.

한 화면이 두 가지 읽기를 동시에 지원한다:

| 읽기 | 소요 | 보는 곳 |
| --- | --- | --- |
| 훑기 | ~5초 | 요약 막대 + 주의 항목 칩 |
| 파고들기 | 제한 없음 | 추이 차트, 항목 펼침 |

훑기를 방해하지 않으면서 파고들기를 막지 않는 것이 이 화면의 설계 조건이다.
그래서 상세는 **기본 접힘**이고, 펼쳐도 페이지를 떠나지 않는다.

---

## 레이아웃과 위계

```
┌─ 건강검진 결과 ────────────────────────────────────┐
│  국민건강보험공단 검진 기록 6회차 (2020 – 2025)     │
├──────────────────────────┬─────────────────────────┤
│ ① 최근 검진 결과          │ ④ 검사 항목             │
│    ─────────────         │    계측 ─────────────   │
│    [■■■■□□▨▨░]           │    키          172 cm   │
│    정상A 8 · 질환의심 3   │    체중        75  kg   │
│                          │    ─────────────────    │
│    주의가 필요한 항목 3   │    혈압 ────────────    │
│    [혈압 142/88] [LDL …] │    수축기  142 ▲질환의심│
│                          │    ⌄ (펼치면 근거)      │
│    ? 판정불가 5개 …       │    …                    │
├──────────────────────────┤                         │
│ ② 항목별 추이  [항목 ▾]   │                         │
│    ┌──────────────────┐  │                         │
│    │ 기준 띠 + 꺾은선  │  │                         │
│    └──────────────────┘  │                         │
│    범례: 정상A 90미만 …   │                         │
├──────────────────────────┤                         │
│ ③ 검진 이력              │                         │
│    2025-03-14 [일반][구강]│                         │
└──────────────────────────┴─────────────────────────┘
```

위계 근거:

1. **요약이 맨 위** — 유일한 "지금 뭘 봐야 하나"의 답. 주의 항목이 없으면
   *"질환의심 항목이 없습니다"*로 명시한다(빈 공간이 아니라 답).
2. **추이가 두 번째** — 판정보다 한 겹 깊지만 여전히 요약이다. 방향을 본다.
3. **이력이 세 번째** — 참조 정보. 언제 어디서 받았는지는 판정과 무관하다.
4. **검사 항목이 오른쪽** — 21개 전량. 훑기에는 필요 없고 파고들기에만 쓰인다.
   ≥1024px에서 옆에 두어 요약과 **동시에** 보이게 한다. 묶음별로 접히고,
   **질환의심이 있는 묶음만 기본 펼침**이다. 접힌 묶음도 머리글에 질환의심 수를 달아
   접기가 정보를 숨기지 않게 한다.

좁은 화면에서는 ①②③④ 순서로 세로로 쌓인다. 훑기 경로가 먼저 오는 순서 그대로다.

### 대시보드는 한 화면에 들어온다

**≥1024px에서 페이지 자체는 스크롤하지 않는다.** 대시보드는 훑는 화면인데
전체가 6천 픽셀이면 훑기가 성립하지 않는다.

- 페이지 높이를 `100dvh`로 고정하고, **넘치는 것은 검사 항목 목록 안에서만** 스크롤한다.
  요약·추이·이력은 항상 보인다 — 그게 "지금 뭘 봐야 하나"의 답이라서다.
- 검사 항목 21개를 다 보여주되 **묶음을 접는다.** 기본은 주의가 필요한 묶음만 펼침.
  잘라내는 게 아니라 접는 것이라 "잘린 항목은 없는 항목" 원칙과 충돌하지 않는다.
- 좁은 화면(<1024px)은 예외다. 세로 스크롤이 자연스러운 환경이라 높이를 고정하지 않는다.

## 상태

| 상태 | 화면 |
| --- | --- |
| **로딩** | 스켈레톤 2장(요약 카드, 차트 카드). 실제 레이아웃과 같은 높이라 로드 시 콘텐츠가 튀지 않는다. `aria-busy="true"` + `aria-label="검진 결과를 불러오는 중"` |
| **로드됨** | 위 레이아웃 |
| **에러** | 전체를 카드 하나로 대체. 제목 *"검진 결과를 불러오지 못했습니다"* + 원인 문장. 재시도 버튼 없음 — Query가 자동 재시도하고, fixture 폴백이 있어 실제 도달이 드물다 |
| **부분** | **정상 경로.** 값 자리에 `측정 안 함`, 차트는 선이 끊기고 *"선이 끊긴 구간은 미측정입니다"*. 기준 없는 항목은 배지 대신 `기준 없음` |
| 빈 상태 | 발생하지 않음 (fixture 폴백) |
| 새로고침 | 없음 (검진 데이터는 실시간이 아니다) |
| 오프라인 | 에러로 흡수 |

## 인터랙션

### 항목 펼치기

행 전체가 버튼이다. 클릭하면 그 자리 아래에 판정 근거가 펼쳐진다.

- 펼침 상태는 **행마다 독립** — 여러 개를 동시에 열어 비교할 수 있다. 아코디언처럼
  하나만 열리게 하면 "LDL과 총콜레스테롤을 나란히 보기"가 불가능해진다.
- 화살표가 180° 회전해 상태를 알린다(`aria-expanded`와 중복 부호화).
- 상세 내용: **판정 기준**(정상A/정상B/질환의심 원문 문자열) + **회차별 값**(최신순, 각
  회차 판정 배지).

기준이 없는 항목을 펼치면 *"검진 기관이 이 항목의 판정 기준을 제공하지 않습니다.
수치만 참고하세요."* — 빈 표를 보여주지 않는다.

### 추이 항목 고르기

`<select>` + `<optgroup>`(계측/혈압/혈액/…). 선택지 라벨에 현재 판정을 붙여
(`총콜레스테롤 · 질환의심`) 열기 전에도 어디를 봐야 할지 보인다.

- **후보는 숫자가 2회 이상 있는 항목만.** 1개짜리는 선이 안 그려진다.
- 기본값: 질환의심 ∩ 기준 띠 그릴 수 있음 → 질환의심 → 첫 항목.

### 차트

- **기준 띠를 배경에**, 데이터 선을 위에. 값이 어느 구간에 있는지 눈으로 읽힌다.
  ApexCharts는 `yaxis annotations`를 시리즈 **뒤에 그리지 않는다** — DOM 순서상 뒤에 와서
  선을 덮는다. `annotations`로 띠를 그리지 말고 차트 뒤에 별도 레이어로 깐다.
- **띠에 라벨을 얹지 않는다.** 구간이 촘촘하면 선·마커와 반드시 겹친다. 어느 띠가
  무슨 판정인지는 차트 아래 범례가 말하고, 범례에 기준 문자열도 함께 둔다.
- Y축을 띠 범위에 맞춘다. 축이 띠보다 넓으면 위아래 여백이 생겨 선이 가장자리에 붙는다.
- 결측은 `null` — 선을 잇지 않는다. 이으면 받지 않은 검사를 받은 것처럼 보인다.
- 애니메이션·줌·툴바 끔. 6점짜리 정적 차트에 필요 없다.

## 미해결

- **2단계 인증 플로우 화면이 없다.** 1차 요청 → 앱 인증 대기(4분 30초) → 2차 요청의
  대기 상태 UX가 설계되지 않았다. 지금은 fixture로 우회한다.

## 해결됨

**성별 입력** — 요약 카드 머리에 남/여 전환을 두고 `entities/user`의 zustand 세션에
보관한다. API가 성별을 주지 않는데 `waist`·`hemoglobin`·`yGPT`는 기준이 성별로 갈리므로,
잘못된 기준으로 조용히 판정하느니 **무엇을 기준으로 봤는지 드러낸다.**
로그인이 붙으면 로그인 폼이 같은 세션 값을 채우고 소비하는 쪽은 바뀌지 않는다.

라벨을 `판정 기준`으로 둔 이유: 이 값은 사용자의 신원이 아니라 **판정에 쓰는 기준**이다.
프로필 설정처럼 보이면 왜 여기 있는지 설명되지 않는다.
