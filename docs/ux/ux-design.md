## 사용자와 목표

**JTBD**: 검진 결과지를 받았을 때, 지금 내 몸에서 **신경 써야 할 게 뭔지** 알고 싶다 —
숫자를 하나씩 해석하지 않고.

열람자는 비전문가 본인이다. `LDL 148`이 무슨 뜻인지 모르고, 알고 싶은 건 "이게 괜찮은
건가"다. 그래서 화면은 **판정을 먼저, 숫자를 나중에** 보여준다.

3번(무엇을 제거할 수 있나)의 답으로 뺀 것:

- **필터·정렬 컨트롤** — 항목 21개는 전부 한 화면에 들어간다. 거를 이유가 없다.
- **회차 선택기** — 최신이 기본이고, 과거는 추이 차트와 상세 펼침에서 본다.
  회차를 고르게 하면 "몇 년 걸 봐야 하지"라는 결정을 사용자에게 떠넘긴다.
- **검색** — 21개는 훑는 게 검색보다 빠르다 (힉의 법칙보다 스캔이 이긴다).

## 정보 구조

라우트는 하나다. 대시보드가 곧 앱이다.

```
/  대시보드 ─┬─ 요약 (판정 분포 · 주의 항목)
             ├─ 항목별 추이 (선택 → 차트)
             ├─ 검진 이력 (방문 날짜 · 기관)
             └─ 검사 항목 (묶음별 목록 → 펼치면 판정 근거)
```

**깊이 0.** 모든 콘텐츠가 한 화면에 있고, 상세는 그 자리에서 펼친다(인라인 disclosure).
페이지 전환이 없으므로 뒤로가기·브레드크럼·내비게이션 바가 전부 불필요하다.

읽는 순서를 왼쪽 열이 강제한다: **요약 → 추이 → 이력**. 오른쪽 열(검사 항목)은 참조용이라
위계상 뒤다. 좁은 화면에서는 이 순서 그대로 세로로 쌓인다.

미구현: 로그인·인증 플로우. 지금은 fixture로 바로 대시보드를 연다.

## 판정 5-state 표현 규칙

단일 출처는
[judgement-display.ts](../../dashboard/src/entities/health-reference/ui/judgement-display.ts)다.
화면은 색을 직접 고르지 않는다.

| 판정 | 라벨 | 형태 | 뜻 |
| --- | --- | --- | --- |
| `suspect` | 질환의심 | ▲ | 기준상 위험 구간 |
| `undetermined` | 판정불가 | ? | 기준은 있는데 어느 구간에도 안 걸림 |
| `normalB` | 정상 B | ◐ | 경계 |
| `normalA` | 정상 A | ● | 정상 |
| `unmeasured` | 미측정 | ○ | 값이 없음 |

**정렬은 나쁜 것부터**(`JUDGEMENT_ORDER`). 요약 막대와 항목 정렬이 같은 순서를 쓴다.

### 판정불가와 기준 없음을 구분한다

둘 다 "판정이 안 나온다"지만 원인이 다르므로 화면이 다르게 말한다.

| 상황 | 화면 | 예 |
| --- | --- | --- |
| 기준 자체가 없는 항목 | 배지 없이 `기준 없음` 회색 텍스트 | 키, 몸무게, 시력, 청력 |
| 기준은 있는데 안 걸림 | `판정불가` 배지 + 상세에 기준 문자열 | LDL 148 (130–139와 160이상 사이) |

전자를 판정불가 배지로 표시하면 로직이 실패한 것처럼 보인다. 기관이 기준을 안 준 것뿐이다.

### 모르는 것을 괜찮은 것으로 표시하지 않는다

미측정·판정불가는 정상 쪽에 합산하지 않는다. 요약 막대에서 독립 구간을 갖고,
판정불가가 있으면 헤더에 문장으로 명시한다 — *"N개 항목이 어느 기준 구간에도 걸리지
않았습니다. 정상이라는 뜻이 아닙니다."*

## 화면 상태 규약

7가지 중 이 앱에 실재하는 것만 설계한다. 없는 상태를 위해 UI를 만들지 않는다.

| 상태 | 처리 | 위치 |
| --- | --- | --- |
| 로딩 | 스켈레톤 (레이아웃 유지, `aria-busy`) | `CheckupOverview` |
| 로드됨 | 기본 | — |
| 에러 | 카드 하나로 대체 + 원인 문장 | `CheckupOverview` |
| 부분 | **정상 경로다.** 결측은 값 자리에 `측정 안 함`, 차트는 선이 끊김 | 항목 행 · 차트 |
| 빈 상태 | 발생하지 않음 — fixture 폴백이 항상 데이터를 준다 | — |
| 새로고침 | 없음 — 검진 데이터는 실시간이 아니다 | — |
| 오프라인 | 에러 상태로 흡수 | — |

**부분 상태가 이 앱의 기본이다.** 6회차 중 지질 4종은 2021·2023이 비고, `osteoporosis`는
전 회차가 빈다. 결측을 예외로 다루면 화면이 계속 고장나 보인다.

스피너를 쓰지 않는다. 스켈레톤이 로드 후 레이아웃과 같은 자리를 차지해서 콘텐츠가
튀지 않는다.

## 인터랙션 규칙

- **행위는 두 개뿐이다** — 항목 펼치기, 추이 항목 고르기. 둘 다 `features/`에 있다.
- **파괴적 액션이 없다.** 읽기 전용 화면이라 확인 다이얼로그·실행 취소가 필요 없다.
- **토스트·모달을 쓰지 않는다.** 알릴 것은 전부 화면 안에 인라인으로 있다.
- **펼침은 그 자리에서.** 상세를 모달로 띄우면 옆 항목과 비교할 수 없다.
- 항목 행 전체가 클릭 타깃이다 (피츠의 법칙 — 배지만 누르게 하지 않는다).

### 선택 컨트롤은 `<select>`다

추이 항목이 17개다. 칩으로 늘어놓으면 가로로 밀어야 하고, **잘린 항목은 없는 항목이다.**
네이티브 `<select>`는 묶음(`<optgroup>`)을 그대로 쓰고, 모바일에서 OS 피커가 뜬다
(야콥의 법칙).

기본 선택은 **질환의심이면서 기준 띠를 그릴 수 있는 항목** — 사용자가 고르기 전에
가장 볼 이유가 큰 것을 이미 보여준다.

## 반응형

**가로 스크롤을 만들지 않는다.** 넘치면 접거나(`flex-wrap`) 세로로 쌓는다.

| 폭 | 레이아웃 |
| --- | --- |
| < 1024px | 한 열. 요약 → 추이 → 이력 → 검사 항목 순으로 쌓임 |
| ≥ 1024px | 두 열 `7fr / 8fr`. 왼쪽 요약·추이·이력, 오른쪽 검사 항목 |

- 항목 한 줄에 이름·값·스파크라인·배지가 다 들어간다. 테이블을 쓰지 않아 320px에서도
  줄바꿈 없이 성립한다.
- 배지·범례·주의 항목은 전부 `flex-wrap` — 좁아지면 다음 줄로 접힌다.
- 차트 컨테이너에 `min-w-0`이 필요하다. ApexCharts가 폭을 재서 SVG를 그리는데,
  제약이 없으면 그리드 트랙까지 밀어낸다.

## 접근성 표준

- **색만으로 판정을 전달하지 않는다.** 5-state는 색 + 텍스트 라벨 + 형태(`shape`)로
  중복 부호화한다. 건강 데이터에서 적록색맹 사용자가 정상/위험을 못 가르는 건 치명적이다.
- 요약 막대는 `role="img"` + 분포를 읽는 `aria-label`. 시각적 비율을 못 보는 사용자도
  같은 정보를 얻는다.
- 펼침 버튼에 `aria-expanded`, 로딩 컨테이너에 `aria-busy`.
- 장식용 아이콘·색점은 `aria-hidden`.
- 명암비 WCAG AA 이상. 배지는 soft 배경 + 진한 글자 조합으로 확보한다.
- `suspect`를 순수 빨강이 아니라 주황 쪽으로 당겨 `normalA`와 명도까지 벌렸다.

## 카피 규칙

- **판정 용어는 검진표 원문을 쓴다** — `정상 A` `정상 B` `질환의심`. 임의로 순화하면
  실제 결과지와 대조가 안 된다.
- **결측은 `측정 안 함`**, `-`나 `N/A`가 아니다. 기호는 오류처럼 보인다.
- **판정불가는 뜻을 덧붙인다** — 배지만으로는 "정상 아님"이 전달되지 않는다.
- **에러는 무엇이 일어났는지 + 어떻게 할지**. 스택 트레이스를 노출하지 않는다.
- 전문 용어를 풀어쓰지 않되, 근거는 상세에서 원문 기준 문자열로 보여준다
  (원칙 3 — 판정 근거를 숨기지 않는다).
