# 건강검진 대시보드

CANDiY API를 연동해 건강검진 결과를 시각화하는 SPA.
6회차(2020–2025) × 검사항목 21개를 판정해 보여준다.

**[배포된 대시보드 열기](https://dashboard-alpha-ten-71.vercel.app)** — 인증 없이 예시 데이터로 바로 보인다.

## 이 제품이 하는 것

검진 결과지는 숫자의 나열이라 **지금 상태가 어떤지, 어느 방향으로 가는지**가 읽히지 않는다.
이 대시보드는 값 하나하나를 API가 준 판정 기준에 대어보고, 그 결과를 세 층으로 보여준다.

| 층 | 무엇을 답하나 |
| --- | --- |
| **상태 요약** | 최신 회차에서 정상·주의가 몇 개인가, 지금 볼 항목은 무엇인가 |
| **추이 차트** | 이 항목이 6년간 어느 방향으로 갔나, 기준 구간 안에 있나 |
| **항목 목록 / 이력** | 개별 값과 판정 근거는 무엇인가 |

핵심 주장은 **판정이 3색으로 안 나뉜다**는 것이다. 요구사항은 초록·주황·빨강이지만 실제
데이터에는 *측정하지 않은 것*과 *기준에 걸리지 않는 것*이 있다. 이 둘을 "정상"으로 뭉개지
않고 별도 상태로 드러낸다 ([판정은 5단계다](#판정은-5단계다)).

## 설치와 실행

전제: **Node 20+**, **pnpm**. 이 저장소는 모노레포 툴을 쓰지 않으므로 명령은
`dashboard/` 안에서 실행한다.

```bash
cd dashboard
pnpm install
pnpm dev            # http://localhost:5173
```

**키 없이도 그대로 동작한다.** 대시보드가 예시 데이터로 열리고, 실 조회(인증)만
`검진 조회 서비스가 설정되지 않았습니다`로 답한다. 화면·판정·차트를 확인하는 데는 키가 필요 없다.

실 API 조회까지 로컬에서 돌리려면 CANDiY 키를 넣는다:

```bash
cp .env.example .env    # API_KEY=... 채우기
```

> **`VITE_` 접두사를 붙이지 않는다.** 붙이는 순간 Vite가 번들에 값을 박아 넣어
> 브라우저에서 키가 그대로 보인다. 키는 서버리스 함수의 `process.env`에서만 읽는다.

`/api/checkup`은 Vercel 서버리스 함수라 `vite dev`가 기본으로는 실행하지 않는다 —
[`vite.config.ts`](vite.config.ts)의 `apiDevServer` 플러그인이 개발 서버에서
같은 함수를 불러 준다. 프록시 로직은 한 벌이고 배포는 Vercel이 같은 파일을 직접 쓴다.

## 평가 기준별 구성

과제 평가 기준 6개에 대해 이 저장소가 무엇으로 답하는지의 지도다. 각 항목의 상세는
아래 해당 절에 있다.

### 1. 코드베이스 — 폴더 구조 · 관심사 분리 · 의존성 관리 · 모듈 단위 분리

- **FSD(Feature-Sliced Design) 6레이어.** `app → pages → widgets → features → entities → shared`.
  배치 기준은 *"이게 뭐냐"면 `entities`, "뭘 한다"면 `features`, "화면 한 덩어리"면 `widgets`*.
- **의존성 방향을 테스트가 강제한다.** 규칙의 단일 출처는
  [`shared/config/fsd.ts`](src/shared/config/fsd.ts)이고
  [`fsd-boundaries.test.ts`](src/shared/config/fsd-boundaries.test.ts)가 실제 import를 파싱해
  위쪽 레이어로의 역참조와 같은 레이어의 슬라이스 간 참조를 잡는다. 문서로만 적힌 규칙이 아니다.
- **세그먼트 규약도 같은 테스트가 강제한다** — `ui/`에서 훅·`fetch` 금지,
  `shared/ui` 밖에서 도메인 콜백 props 금지.
- **판정 도메인이 격리돼 있다.** `entities/health-reference`는 `@/shared` 외에 아무것도
  import하지 않는다 — React도 API도 `checkup`도 모른다. 그래서 fixture나 렌더링 없이
  입출력만으로 테스트된다.
- 자세히: [구조](#구조) · [기준 문자열 파서](#기준-문자열-파서)

### 2. UI 설계 — 대시보드 구조 · 시각화 · 반응형 · 로딩/에러

| 요구 | 어떻게 |
| --- | --- |
| 대시보드 구조 | 요약 → 추이 → 상세의 3층. `≥1024px`에서 **페이지가 스크롤되지 않고** 넘치는 것은 항목 목록 안에서만 스크롤한다 |
| 시각화 | 추이 차트 배경에 기준 구간을 띠로 깔아 **선이 어느 띠에 있는지가 곧 판정**이다. 결측 회차는 선을 끊는다 |
| 반응형 | 모바일 1열 → `lg` 2단 → `xl` 검사 묶음 2열 → `2xl` 폭 확장. **가로 스크롤을 만들지 않는다** — 잘린 항목은 없는 항목이다 |
| 로딩 | 스켈레톤 + `aria-busy`. 인증 대기는 5분 카운트다운 |
| 에러 | 조회 실패 시 **덮어쓰지 않는 것이 폴백**이다. 화면은 직전 데이터를 유지하고 사유만 알린다. 상태코드별로 **다음에 뭘 할지**를 나눠 말한다 ([실패는 원인별로 다르게 말한다](#실패는-원인별로-다르게-말한다)) |
| 막다른 화면 | 없는 주소(404)와 렌더 오류를 같은 껍데기로 잡는다. 기본 `Not Found`와 흰 화면을 남기지 않는다 |
| 접근성 | 판정을 **색만으로 전달하지 않는다** — 색 + 라벨 + 형태(`● ◐ ▲ ○ ?`) 3중 부호화 |

설계 근거는 [`docs/ux/`](../docs/ux)와 [`PRODUCT.md`](../PRODUCT.md)에 있다.
자세히: [화면](#화면)

### 3. API 연동 — 요청/응답 정확성 · 인증 헤더 · 요청 인자

- **2단계 인증을 실제로 구현했다.** 1차 요청(`inquiryType:"0"`) → 응답 `.data` 보관 →
  사용자 앱 인증(5분) → 2차 요청(`isContinue:"1"` + `multiFactorInfo`).
- **인증 헤더는 브라우저에 없다.** `x-api-key`는 서버리스 함수
  [`api/checkup.ts`](api/checkup.ts)의 `process.env`에서만 읽는다. CANDiY가 CORS 헤더를
  주지 않아(직접 확인: `OPTIONS` → 403) 프록시가 불가피했는데, 그 제약이 키 노출 문제까지 같이 풀었다.
- **응답의 함정을 정규화에서 흡수한다** — 스칼라가 전부 string이고 빈 문자열이 결측,
  `overviewList`와 `resultList`의 **정렬 방향이 반대**다.
- **미검증 값을 보내지 않는다.** 알뜰폰 3종은 모회사 망 코드로 변환해 보낸다 — 전용 코드가
  있는지 probe로 확인되지 않았고, 미검증 값은 인증을 조용히 실패시킨다.
- 요청 형태의 검증된 출처는 [`scripts/probe-candiy.sh`](scripts/probe-candiy.sh)다 — 실제로 호출해 확인한 것.
- 자세히: [2단계 인증과 프록시](#2단계-인증과-프록시) · [데이터](#데이터)

### 6. 협업 — 커밋 단위와 메시지

- **커밋의 단위는 관심사다.** 기능 하나를 바꿨으면 그 기능 하나가 한 커밋이고,
  파서를 고치면서 스타일을 정리했으면 커밋 2개다.
- **형식을 훅이 강제한다.** [`.githooks/commit-msg`](../.githooks/commit-msg)가
  `<type>(<scope>): <제목>` 형식과 제목 60자(한글 포함 **문자 수**)를 검사한다.
  템플릿은 [`.gitmessage`](../.gitmessage).
- pre-commit 훅은 `dashboard/src/` 변경 시 FSD 경계 테스트를 돌린다 — 아키텍처 위반이
  커밋으로 들어가지 않는다.
- 제목은 **무엇을 왜** 바꿨는지 말한다. 한 문장에 안 담기면 커밋이 크다는 신호로 보고 쪼갠다.
  ```
  fix(dashboard): 인증으로 받은 실 데이터가 예시로 덮이던 것 수정
  refactor(user): 성별 스토어 이름을 판정 기준으로 정정
  feat(checkup): CANDiY 1차·2차 요청 레이어 추가
  ```

## 판정은 5단계다

요구사항은 초록·주황·빨강 3색이지만 **데이터가 3색으로 나뉘지 않는다.**
API의 `refType` 4종에 실제 값을 맞춰보면 두 경우가 더 생긴다.

| 판정 | 언제 |
| --- | --- |
| `normalA` `normalB` `suspect` | 값이 해당 구간에 걸렸다 |
| `unmeasured` | 측정값이 없다 (빈 문자열) |
| `undetermined` | 어느 구간에도 안 걸렸거나, 기준을 해석하지 못했다 |

미측정과 판정불가를 "정상"으로 뭉개지 않는다. 건강 데이터에서 *모르는 것*을
*괜찮은 것*으로 표시하는 건 사실과 다르다.

fixture 6회차를 판정하면 **정상 70 · 판정불가 30 · 미측정 14 · 질환의심 12** 가 나온다.
판정불가 30건 중 24건은 신장·체중·시력·청력으로, **기준 자체가 제공되지 않는** 항목이다.
화면에서는 이 둘을 구분한다 — 전자는 "기준 없음"으로 수치만, 후자는 판정불가 배지를 단다.

## 기준 문자열 파서

`referenceList`가 판정 기준을 자연어로 준다. 같은 `/`가 항목마다 다른 뜻이라
범용 처리를 하면 반드시 틀린다.

| `/`의 의미 | 항목 | 예 |
| --- | --- | --- |
| 성별 분기 | 허리둘레·혈색소·감마지티피 | `남: 13-16.5 / 여: 12-15.5` |
| 수축기/이완기 | 혈압 | `140이상 또는 /90이상` |
| 구간 합집합 | 체질량지수 | `18.5미만/25~29.9` |
| 좌/우 | 시력·청력 | `1.2/1.0` (기준 없음) |

파서는 문자열을 중간표현(`Criterion`)으로 옮기고, 해석하지 못하면 `null`을 준다.
**예외 테이블을 두지 않는다** — 기준을 추측해서 판정하느니 판정불가로 남긴다.

### 회귀 기준

`lib/judge.test.ts`가 고정한다. 이 값들이 바뀌면 파서가 망가진 것이다.

| 케이스 | 기대 | 왜 |
| --- | --- | --- |
| 2022 `LDL=148` | 판정불가 | 정상B `130-139`와 질환의심 `160이상` **사이 공백** |
| 2024 `Hb=16.8` | 판정불가 | 남 정상A 상한 `16.5` 초과, 어느 구간에도 없음 |
| 2025 `BP=142/88` | 질환의심 | `140이상 또는 /90이상`의 OR에서 **수축기만** 걸림 |
| 2021·2023 지질 4종 | 미측정 | 격년 검사라 통째로 결측 |

**판정은 나쁜 쪽부터 매칭한다.** 혈압 `142/88`은 정상B(`120-139 또는 /80-89`)의
이완기 조건과 질환의심의 수축기 조건에 동시에 걸린다. OR 기준이 겹치는 이상
답은 나쁜 쪽이다.

## 화면

모바일 우선. 한 항목 = 한 줄이라 좁은 화면에서 가로 스크롤이 없고,
넓은 화면에서는 요약·추이·이력을 왼쪽, 항목 목록을 오른쪽에 나눈다.

**≥1024px에서 페이지 자체는 스크롤하지 않는다.** 대시보드는 훑는 화면인데 전체가
수천 픽셀이면 훑기가 성립하지 않는다. 넘치는 것은 검사 항목 목록 안에서만 스크롤하고,
요약·추이·이력은 항상 보인다. 검사 묶음은 **접지 않는다** — 21개 항목이 항상 보이고,
머리글은 구분자 역할만 하며 질환의심 수를 달아 어느 묶음을 볼지 먼저 읽힌다.
≥1280px에서는 묶음을 두 열에 나눠 담아([split-columns.ts](src/widgets/checkup-overview/lib/split-columns.ts))
21개가 세로로 들어간다. 접기는 공간이 부족할 때의 수단인데, 2열에서는 공간이 남기 때문이다.

- **상태 요약** — 최신 회차 판정 분포를 비율 막대로. 그 아래 주의가 필요한 항목.
  머리에 **남/여 전환**이 있다 — API가 성별을 주지 않는데 허리둘레·혈색소·감마지티피는
  기준이 성별로 갈려서, 잘못된 기준으로 조용히 판정하느니 무엇을 기준으로 봤는지 드러낸다
- **추이 차트** — 배경에 기준 구간을 띠로 깔아 선이 어느 띠에 있는지가 곧 판정이다.
  띠를 ApexCharts `annotations`로 그리지 않는다 — DOM 순서상 시리즈 뒤에 와서 **선을 덮는다.**
  차트 뒤에 별도 배경 레이어로 깔고 그 위에 투명한 차트를 얹는다.
  띠 위에 라벨도 얹지 않는다. 범례가 기준 문자열과 함께 말한다.
  결측 회차는 선을 끊는다 — 이으면 받지 않은 검사를 받은 것처럼 보인다
- **항목 선택** — 17개를 칩으로 늘어놓으면 가로로 밀어야 해서 `<select>`를 쓴다.
  **가로 스크롤을 만들지 않는다** — 잘린 항목은 사용자에게 없는 항목이다
- **항목 목록** — 탭하면 판정 기준 원문과 6회차 값이 펼쳐진다

**색만으로 판정을 전달하지 않는다.** 5단계는 색 + 라벨 + 형태(`● ◐ ▲ ○ ?`)로
중복 부호화한다. 적록색맹 사용자가 정상과 위험을 구분 못 하면 치명적이다.

## 데이터

**기본은 예시 데이터다.** 링크를 열면 인증 없이 바로 대시보드가 보인다
([`shared/api/__fixtures__`](src/shared/api/__fixtures__)). 부제에 `예시 데이터`가 붙어
지금 보는 게 실제 기록이 아님을 밝힌다.

실 데이터는 `내 검진 결과 불러오기` → [`/login`](src/pages/auth)에서
2단계 인증(간편인증 12종 중 택1, 5분)을 거친다. 인증을 안 해도 화면이 온전히 보이는 이유는
실 데이터와 fixture가 **같은 정규화 경로**를 지나기 때문이다.

**실패해도 폴백 코드가 없다.** 2차 응답이 성공하면 Query 캐시
(`checkupKeys.history()`)를 덮어쓰고, 실패하면 안 덮는다 — 덮지 않는 것이 곧 폴백이다.
`try/catch`도 `?? fixture`도 필요 없다.

응답에서 주의할 것:

- 스칼라가 전부 string이고 **빈 문자열이 결측**이다 (`caseType`만 number)
- **정렬 방향이 섞여 있다** — `overviewList`는 오래된 순, `resultList`는 최신순.
  정규화에서 방향을 고정한다
- `resultList`는 날짜당 일반·구강 2건. 안정 정렬이라 순서가 입력에 좌우되므로
  일반을 먼저 두도록 명시한다

## 2단계 인증과 프록시

**CANDiY는 CORS 헤더를 주지 않는다.** 직접 확인했다 —
`OPTIONS /v1/nhis/checkup`이 403을 주고 `access-control-*` 헤더가 하나도 없다.
브라우저에서 직접 부를 수 없으므로 서버를 거치는 것 외에 방법이 없다.

그래서 [`api/checkup.ts`](api/checkup.ts) 서버리스 함수가 프록시한다.
**이게 API 키 노출 문제까지 같이 해결한다** — `API_KEY`에 `VITE_` 접두사가 없어서
번들에 들어가지 않는다. 제약이 강요한 우회가 보안 결정과 같은 답이었다.

```
폼 → 1차 요청 (inquiryType:"0", loginTypeLevel:<폼에서 고른 값>)
   → 응답의 .data 통째로 보관
   → 사용자가 고른 앱에서 인증 (5분)
   → 2차 요청 (isContinue:"1" + multiFactorInfo:<1차 .data>)
   → Query 캐시에 주입 → 대시보드
```

- **인증 수단은 고정하지 않는다.** 12종을 로고 그리드로 펼쳐 고르게 한다 — 하나로 박으면
  그 앱을 안 쓰는 사람은 조회 자체를 못 한다. probe로 실제 검증한 값은 `8`(토스)
  하나뿐이고, 나머지는 CANDiY 스펙 표기를 따랐다.
- **통신사는 화면에 6개, API에는 3개다.** 알뜰폰 3종은 모회사 망 코드(`0`/`1`/`2`)를
  그대로 보낸다. 알뜰폰용 별도 코드를 받는지 probe로 확인되지 않았고, 미검증 값을
  보내면 인증이 조용히 실패한다. 변환은 [`build-body.ts`](src/features/checkup-inquiry/lib/build-body.ts)가 한다.
- **휴대폰 번호는 화면에서만 하이픈이 붙는다.** 상태와 요청 바디는 숫자 11자리 그대로다
  ([`format-phone.ts`](src/features/checkup-inquiry/lib/format-phone.ts)).

- **`multiFactorInfo`는 1차 응답의 `.data`를 통째로** 넣는다. 일부만 골라 넣으면 실패한다.
  프록시도 바디를 파싱하지 않고 원문을 그대로 넘긴다.
- **5분을 함수가 붙잡지 않는다.** 대기는 브라우저가 하고 함수는 요청 1건씩
  짧게 끝난다. 서버리스에서 5분을 잡고 있으면 실행 제한에 걸린다.
- **폴링하지 않는다.** 사용자가 `인증을 완료했습니다`를 누를 때 2차를 1회 보낸다.
  검증된 출처([`probe-candiy.sh`](scripts/probe-candiy.sh))가 그 형태이고, 인증 완료 전
  호출의 동작은 확인되지 않았다 — 모르는 채로 반복 호출하면 인증 세션을 스스로 깨뜨릴 수 있다.
- 프록시는 인증 없이 공개되므로 **필수 필드를 서버에서도 검증한다.**
  안 하면 남의 키로 임의 요청을 대신 쏴주는 오픈 프록시가 된다.
- **제한 시간은 5분이다.** NHIS `checkup`의 문서상 제한이고, 270초(4분 30초)는
  HIRA(`medical_record`)의 간편인증 제한이라 이 엔드포인트의 값이 아니다.
  화면 문구는 `AUTH_WINDOW_MS`에서 만든다 — 숫자를 문장에 박으면 상수만 고쳤을 때
  화면이 다른 시간을 말한다. 조사(`이`/`가`)도 값에서 정한다
  ([`josa.ts`](src/shared/lib/josa.ts)).
- **`?response_type=candiy`를 명시한다.** 생략해도 같은 형태로 오지만(probe가 이
  파라미터 없이 받은 `.data` 키가 문서의 `candiy` 예시와 같다) 기본값이 바뀌면
  파서가 조용히 깨진다. 우리가 아는 형태를 요청에 적어 둔다.
- **보안숫자 3회 실패는 감지하지 못한다.** CANDiY가 보안숫자를 AI로 자동 처리하고
  3회 실패하면 수동 입력이 필요해지는데, 그 상태를 응답에서 어떻게 알리는지는
  확인되지 않았다(probe가 성공 경로만 캡처). 감지하는 대신 만료 화면에서 미리 알린다 —
  반복 실패하는 사용자에게 "또 시도하세요"만 반복하면 막다른 길이 된다.

**성별은 인증 폼에서 받는다.** API 응답에 성별이 없는데 허리둘레·혈색소·감마지티피는
기준이 성별로 갈린다. 예시 데이터는 남성 기준으로 판정하고, 성별이 판정을 어떻게 바꾸는지는
[`sex.test.ts`](src/entities/health-reference/lib/sex.test.ts)가 고정한다
(혈색소 12.5는 남 정상B, 여 정상A).

### 실패는 원인별로 다르게 말한다

"실패했습니다" 하나로 뭉치면 **재시도하면 될 일과 입력을 고쳐야 할 일이 구분되지 않는다.**
사용자는 고칠 수 없는 것을 고치려 하거나, 고칠 수 있는 것을 포기한다.

분기는 [`error-message.ts`](src/features/checkup-inquiry/lib/error-message.ts)의 순수 함수
하나가 하고 [테스트](src/features/checkup-inquiry/lib/error-message.test.ts)가 고정한다.
API 원문 메시지는 노출하지 않는다(카피 규칙) — 상태코드만 보고 우리 문장을 고른다.

| 원인 | 무엇을 말하나 |
| --- | --- |
| 네트워크 (`fetch` reject) | 연결을 확인하고 다시 시도. **상태코드가 없다** — 응답 자체가 없어서 분기할 수 없다 |
| `400` `422` | 이름·생년월일·번호가 가입 정보와 같아야 한다 — 사용자가 고칠 수 있다 |
| `401` `403` | 권한 확인 실패. 사용자가 고칠 게 없으므로 입력을 의심하게 만들지 않는다 |
| `408` `504` | 응답 지연. 인증 제한 시간과 겹칠 수 있어 "처음부터 다시"라고 말한다 |
| `429` | 다시 시도할 **시점**(1분 뒤)을 준다 |
| `5xx` | 서버 문제. 입력 이야기를 꺼내지 않는다 |

`NO_API_KEY`만 별도 예외 타입(`ApiKeyMissingError`)이다 — 키 없는 배포본은 사용자가
아무것도 할 수 없는 상태라 재시도를 권하면 안 된다.

두 요청(1차·2차)이 같은 `post()`를 지나므로 분기가 **한 곳에만** 있다.

## 배포

**[배포된 대시보드](https://dashboard-alpha-ten-71.vercel.app)** — 인증 없이 바로 보인다.

Vercel에 정적 빌드와 서버리스 함수를 함께 올린다. 설정은 [`vercel.json`](vercel.json)에 있다 —
SPA rewrite(`/(.*)` → `/index.html`)와 프록시 함수의 `maxDuration`.

| 항목 | 값 |
| --- | --- |
| Root Directory | **`dashboard`** |
| Framework | Vite (자동 감지) |
| Build / Output | `pnpm build` / `dist` (자동) |
| 환경변수 | `API_KEY` — **`VITE_` 접두사를 붙이지 않는다** |

**Root Directory를 `dashboard`로 잡는 것이 핵심이다.** 저장소 루트에 `package.json`도
lockfile도 없고(패키지 2개가 각각 갖는다), `vercel.json`이 여기 있다. 루트로 잡으면
프레임워크 감지도 SPA rewrite도 실패한다.

대시보드에서 연결하는 대신 CLI로도 된다:

```bash
cd dashboard
pnpm dlx vercel link
pnpm dlx vercel env add API_KEY production
pnpm dlx vercel --prod
```

`API_KEY`에 접두사가 없어야 Vite가 번들에 주입하지 않는다. 붙이는 순간 키가 공개된다.
저장 후 **재배포해야** 적용된다 (기존 배포에 소급되지 않는다).

**키가 없어도 배포는 동작한다.** 대시보드가 예시 데이터로 열리고, 인증만
`검진 조회 서비스가 설정되지 않았습니다`로 답한다. 평가자가 키 없이 링크만 열어도
화면이 온전히 보이는 것이 이 설계의 목적이다.

`api/`는 [`tsconfig.node.json`](tsconfig.node.json)의 `include`에 넣었다.
안 넣으면 `tsc -b`가 함수를 건너뛰어 **빌드는 통과하고 런타임에 터진다.**

**Docker를 제공하지 않는다.** 산출물이 정적 파일 + 서버리스 함수 하나뿐이라
컨테이너를 얹으면 함수를 실행할 런타임(Express 등)을 따로 만들어야 하고, 그 순간
프록시 로직의 실행 경로가 Vercel용과 컨테이너용 둘로 갈린다. 지금은 개발 서버조차
같은 [`api/checkup.ts`](api/checkup.ts) 한 벌을 쓴다.

## 구조

FSD. 규칙의 단일 출처는 [`shared/config/fsd.ts`](src/shared/config/fsd.ts)이고
[`fsd-boundaries.test.ts`](src/shared/config/fsd-boundaries.test.ts)가 강제한다.

```
entities/health-reference  판정 도메인(순수 함수) + 판정 배지·색 체계
entities/checkup           응답 정규화, Query 훅, 검사 항목 행·상세·이력 표현
entities/user              판정에 쓸 성별 (zustand) — 신원이 아니라 판정 기준이다
features/measurement-detail  항목을 펼쳐 판정 근거를 확인하는 행위
features/trend-explorer      항목을 골라 추이를 보는 행위 (기준 띠 계산 포함)
features/checkup-inquiry     2단계 인증으로 검진 결과를 조회하는 행위
widgets/checkup-overview     엔티티·피처 조립 + 요약 집계
pages/dashboard              위젯 조립
pages/auth                   인증 화면 조립
pages/error                  404 · 렌더 오류 화면 (루트 라우트가 물린다)
shared/ui                    도메인 없는 프리미티브 — Card, Field, Input, Select,
                             Button, ChoiceGrid(로고 타일 라디오 그룹),
                             ErrorScreen(막다른 화면 껍데기)
shared/lib                   React를 모르는 순수 함수 (aria 배선 등)
shared/api                   fetcher + fixture
```

`shared`만 배럴 없이 파일을 직접 import한다 (`@/shared/ui/Input`) — 경계 테스트의
명시적 예외다. `shared/ui`의 프리미티브는 `onClick`·`onChange` 같은 **DOM 콜백만**
받는다. 도메인 의미를 가진 콜백은 여기서도 금지다.

`health-reference`가 `checkup`을 모르고 그 반대도 마찬가지다 —
같은 레이어의 슬라이스끼리는 참조하지 않고 위젯에서 합쳐진다.
`Measurement<TJudgement>`가 제네릭인 것도 이 때문이다: `checkup`은 판정 타입을
import할 수 없어서, 실제 타입으로 좁히는 건 둘이 만나는 위젯의 몫이다.

**경계 테스트가 통과해도 배치가 맞는 건 아니다.** 테스트는 잘못된 방향의 import만
잡지, 전부 위젯에 몰아넣은 것은 못 잡는다. 도메인 개념 하나를 그리면 `entities/ui`,
사용자 행위면 `features`, 조립이면 `widgets`다.

계산은 컴포넌트에 두지 않는다. 날짜별 그룹핑·판정 집계·축 눈금 계산은 전부 `lib/`의
순수 함수이고 각각 테스트가 있다 — 렌더링 없이 입출력만으로 검증된다.

## 아직 안 한 것

- **인증 실패를 상태코드까지만 나눈다.** HTTP 상태로는 갈랐지만
  ([실패는 원인별로](#실패는-원인별로-다르게-말한다)), 같은 코드 안에서 *사용자 거절*과
  *입력 불일치*를 구분하려면 CANDiY의 실패 응답 **본문** 형태를 알아야 하는데 probe가
  성공 경로만 캡처했다. 본문 코드로 갈라야 할 자리는 상태코드 문장으로 덮어 두고,
  실제 실패 응답을 본 뒤 쪼갠다 — 추측으로 분기하면 모르는 코드에서 틀린 안내를 한다
- **인증 수단 로고 파일이 없다.** `ChoiceGrid`가 `/auth/<slug>.svg`를 찾고, 없으면
  브랜드색 배경 + 짧은 글자로 폴백한다. `public/auth/`에 파일을 떨구면 코드 수정 없이
  로고로 바뀐다 — 지금 보이는 색 타일이 그 폴백이다
